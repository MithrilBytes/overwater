overwater

Finds LLM call sites where the model is bigger, pricier, or more wastefully configured than the task in front of it.

Reads your code, prices every call against a public model catalog, and nominates cheaper candidates in dollars per month. In CI it fails builds on new findings and passes the ones already recorded in a baseline.

$ go install github.com/MithrilBytes/overwater/cmd/overwater@latest

What a finding looks like

Every finding renders five fields, in this order. Findings are nominations: a scanner cannot know a cheaper model is safe for your task, so each one states the condition under which you should not switch. That condition ships as a sentence and as numbers, and overwater eval generates a script that exits on them, so CI reads an exit code rather than a report.

$ overwater scan .

Call site: src/classify.ts:57 (classification: temp 0, JSON schema; high confidence)
Current:   claude-opus-5 at ~$91/mo at estimated volume
Candidate: claude-haiku-4-5, same capability tier for this task class, ~$18/mo
Tripwire:  If eval agreement drops below 97%, stay put
Flag:      No prompt caching on a 1,191-token repeated system prompt

When nothing clears the confidence bar the whole verdict is Keep the models you have.  overwater eval generates the A/B script that tests a tripwire.

Install

Go
$ go install github.com/MithrilBytes/overwater/cmd/overwater@latest
Script
$ curl -fsSLO https://raw.githubusercontent.com/MithrilBytes/overwater/main/scripts/install.sh && sh install.sh v2.6.0
Container
$ docker run --rm -v "$PWD:/src" ghcr.io/mithrilbytes/overwater:v2.6.0 scan /src
Nix
$ nix run github:MithrilBytes/overwater

Release binaries for macOS, Linux, and Windows ship with a SHA256SUMS file and a signed build provenance attestation. The install script checks the digest, and checks the attestation too where gh is available. That second check is the one that survives someone who can replace the binary and the digest together, so the GitHub Action fails closed on it rather than trusting a checksum.

Homebrew, scoop, and winget manifests are generated into the repository on every release and deliberately published nowhere. Each would be a second repository to keep current, and the routes above already cover every platform the binaries are built for, so brew install overwater and its equivalents are not meant to work. The manifests exist so that publishing stays a decision rather than a project.

CI

Record a baseline once, commit it, and only new findings fail the build.

- uses: actions/checkout@v4
- uses: MithrilBytes/overwater@v2
  with:
    baseline: .overwater.json

Add pr-comment: true for a sticky verdict comment, which needs pull-requests: write. Add incremental: true on PR builds. Exit codes are 0 clean, 1 findings under the failure policy, 2 operational error. They are never conflated.

How it reads a call site

Four layers feed a rules engine. Every rule, threshold, and price lives in YAML; the engine holds no numbers.

01

Manifests

package.json, requirements.txt, pyproject.toml, go.mod, Gemfile, pom.xml, build.gradle, *.csproj, composer.json, Cargo.toml, Package.swift.

When a manifest declares an SDK and no call site resolves anywhere in the repository, that is said on stderr. The scanner knows the code talks to a model, so silence there would be the difference between nothing to fix and nothing found.

02

Model strings

The catalog is the dictionary: 88 entries across 15 providers, matched by id and alias, in any case. Strings that look like models but are not in the catalog are named on stderr as unpriced, so a model we do not carry cannot read as a clean bill of health.

Only code calls a model. Documentation, test files and configuration rosters are read as context but report no call sites of their own. Calls that spend tokens without naming a model, an HTTP call whose model is a runtime variable or a shell script running claude --print, are named as unpriced rather than guessed at.

03

Call shape

Temperature, token caps, schemas, tools, streaming, reasoning effort, retries, cache control, system prompt size. JavaScript, TypeScript, Python, Go, Ruby, C#, PHP, shell, and notebooks parse as key value pairs; Java, Kotlin, Rust, Scala, and Swift parse as builder chains. Signals are read from the call's own bracket balanced extent, over source with comments and prose masked out.

04

Archetype

Extraction, classification, summarization, chat, agentic, embedding, translation, reranking, moderation, transcription, vision, codegen. Scored from the enclosing function name, the resolved prompt, the SDK method, schema semantics, and the token cap read as intent. A negated phrase does not score.

Call sites carry fan in. A helper that wraps the SDK is priced for its callers, so a wrapper called two hundred times costs two hundred leaf calls. Without measured traffic every dollar figure says at estimated volume; feed in a volumes file or a provider usage export and it reads at measured volume instead.

Catalog

One YAML file per model, validated and emitted as a single versioned catalog.json embedded in the binary. Entries carry prices, context window, capability flags, cache and batch rates, release and deprecation dates, and a source URL. Retired models stay in the catalog; legacy code still references them, and the deprecated-model rule needs their dates.

Contributors update a price by editing one file. A nightly job diffs the catalog against LiteLLM and opens a PR when a provider moves a price, and names any model upstream has started pricing that this catalog does not carry. Merging that PR tags and releases on its own, so a price the catalog accepts reaches the binaries without a human picking a version.

Releases

v2.6 current
The Action verifies build provenance instead of a checksum committed into action.yml. A digest cannot exist until the artifacts are built, so every earlier tag shipped the previous release's digests and only the floating v2 resolved. A version is knowable in advance, so a tag names its own release now and an exact pin works.
v2.5
The tool audited against itself for security, currency and whether it works on repositories nobody wrote for it. A config value bound to a model key was reprinted verbatim on stderr, which the Action pastes into a PR comment. A scanned filename could close the fence around the report. A symlinked root read nothing and called it clean. Bedrock ids were invisible and Converse lost its temperature. Reasoning models were priced as though thinking were free. Three rules added, and layer 1 finally speaks.
v2.4
Layer 2 was measured against 128 real repositories and had been treating any catalog id in any file as a call. Of the ones calling no LLM, 19 reported findings before and 9 do now. A monorepo scan went from 242 seconds to 8. Every rule has an end to end fixture, the ratchet survives a rename, and each release pins the Action itself.
v2.3
Merging a price-watch PR tags and releases on its own. Applying a price carries the cache rates with it.
