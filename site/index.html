overwater

Finds LLM call sites where the model is bigger, pricier, or more wastefully configured than the task in front of it.

Reads your code, prices every call against a public model catalog, and nominates cheaper candidates in dollars per month. In CI it fails builds on new findings and passes the ones already recorded in a baseline.

$ go install github.com/MithrilBytes/overwater/cmd/overwater@latest

What a finding looks like

Every finding renders five fields, in this order. Findings are nominations: a scanner cannot know a cheaper model is safe for your task, so each one states the condition under which you should not switch.

$ overwater scan .

Call site: src/classify.ts:57 (classification: temp 0, JSON schema; high confidence)
Current:   claude-opus-5 at ~$135/mo at estimated volume
Candidate: claude-haiku-4-5, same capability tier for this task class, ~$27/mo
Tripwire:  If eval agreement drops below 97%, stay put
Flag:      No prompt caching on a 1,191-token repeated system prompt

When nothing clears the confidence bar the whole verdict is Keep the models you have.  overwater eval generates the A/B script that tests a tripwire.

Install

Go
$ go install github.com/MithrilBytes/overwater/cmd/overwater@latest
Script
$ curl -fsSLO https://raw.githubusercontent.com/MithrilBytes/overwater/main/scripts/install.sh && sh install.sh v2.3.1
Container
$ docker run --rm -v "$PWD:/src" ghcr.io/mithrilbytes/overwater:v2.3.1 scan /src
Nix
$ nix run github:MithrilBytes/overwater

Release binaries for macOS, Linux, and Windows ship with a SHA256SUMS file and build provenance attestation. The install script verifies the checksum for you.

Homebrew, scoop, and winget manifests are generated into the repository on every release, but none of the three is published yet: there is no tap, no bucket, and nothing submitted to winget-pkgs. Until they are, install by one of the routes above.

CI

Record a baseline once, commit it, and only new findings fail the build.

- uses: actions/checkout@v4
- uses: MithrilBytes/overwater@v2.3.1
  with:
    baseline: .overwater.json

Add pr-comment: true for a sticky verdict comment, which needs pull-requests: write. Add incremental: true on PR builds. Exit codes are 0 clean, 1 findings under the failure policy, 2 operational error. They are never conflated.

How it reads a call site

Four layers feed a rules engine. Every rule, threshold, and price lives in YAML; the engine holds no numbers.

01

Manifests

package.json, requirements.txt, pyproject.toml, go.mod, Gemfile, pom.xml, build.gradle, *.csproj, composer.json, Cargo.toml, Package.swift.

02

Model strings

The catalog is the dictionary: 88 entries across 15 providers, matched by id and alias. Strings that look like models but are not in the catalog are reported at low confidence.

03

Call shape

Temperature, token caps, schemas, tools, streaming, reasoning effort, retries, cache control, system prompt size. JavaScript, TypeScript, Python, Go, Ruby, C#, PHP, shell, and notebooks parse as key value pairs; Java, Kotlin, Rust, Scala, and Swift parse as builder chains. Signals are read from the call's own bracket balanced extent, over source with comments and prose masked out.

04

Archetype

Extraction, classification, summarization, chat, agentic, embedding, translation, reranking, moderation, transcription, vision, codegen. Scored from the enclosing function name, the resolved prompt, the SDK method, schema semantics, and the token cap read as intent. A negated phrase does not score.

Call sites carry fan in. A helper that wraps the SDK is priced for its callers, so a wrapper called two hundred times costs two hundred leaf calls. Without measured traffic every dollar figure says at estimated volume; feed in a volumes file or a provider usage export and it reads at measured volume instead.

Catalog

One YAML file per model, validated and emitted as a single versioned catalog.json embedded in the binary. Entries carry prices, context window, capability flags, cache and batch rates, release and deprecation dates, and a source URL. Retired models stay in the catalog; legacy code still references them, and the deprecated-model rule needs their dates.

Contributors update a price by editing one file. A nightly job diffs the catalog against LiteLLM and opens a PR when a provider moves a price. Merging that PR tags and releases on its own, so a price the catalog accepts reaches the binaries without a human picking a version.
